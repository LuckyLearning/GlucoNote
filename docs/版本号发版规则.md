# 版本号发版规则（X.Y.Z · 仅修订号递增）

> 适用范围：本项目所有正式发版。本规则固定采用三段式版本号，且**仅允许第三位修订号单向 +1**，前两段长期冻结。
> 目的：让版本演进可预期、可审计、无歧义，避免跳号、回退、格式漂移带来的排查与兼容问题。

---

## 1. 版本格式定义

### 1.1 标准形态

```
X.Y.Z
```

- **X（主版本号 / Major）**：项目级大版本标识。
- **Y（次版本号 / Minor）**：项目级小版本标识。
- **Z（修订号 / Patch）**：**唯一允许在发版时变动的字段**，每发一版 +1。

### 1.2 各段取值与书写约束

| 约束项 | 规则 |
| --- | --- |
| 段数 | 固定 3 段，段间用**英文句点 `.`** 分隔，不允许使用其他分隔符 |
| 字符 | 每段为**非负十进制整数**，不允许字母、符号或空格 |
| 前导零 | **禁止**（如 `1.0.05` 非法；`1.0.5` 合法） |
| 取值下限 | 每段 ≥ 0 |
| 取值上限 | 建议单段 ≤ 9999；超过时按实际工程承载上限执行，但**不得回绕归零** |
| 总长度 | 无硬性限制，但应保持简洁可读 |

### 1.3 初始版本

- 项目首个对外版本定义为 **`X.Y.0`**（X、Y 由立项时确定，例如 `1.0.0`）。
- 初始版本即占用该 X.Y 组合下 Z=0 这一编号，后续发版从 `X.Y.1` 起算。

> 注：本规则下 X、Y 一旦确立即**冻结不再变更**（见 §2.2），因此 `X.Y.Z` 实质等价于一个以 `X.Y.` 为前缀、从 0 开始单调递增的修订计数器。

---

## 2. 递增约束

### 2.1 单步单调递增（核心约束）

设上一发版版本为 `X.Y.Z_prev`，本次发版版本为 `X.Y.Z_new`，则必须满足：

```
Z_new = Z_prev + 1
```

即：**每次发版只能将修订号恰好加 1**。

### 2.2 三段约束明细

| 约束 | 说明 | 违规示例 |
| --- | --- | --- |
| **禁止跳号** | 只能 +1，不得 +2 及以上 | `1.0.3 → 1.0.5` ✗ |
| **禁止回退** | Z 只能增大，不得减小或复用历史值 | `1.0.4 → 1.0.3` ✗ |
| **前两段冻结** | X、Y 自初始版本后**永不变更** | `1.0.5 → 1.1.5` ✗ |
| **格式一致** | 始终 3 段、无前导零、纯数字 | `1.0.5 → 1.0.05` ✗ |
| **编号唯一** | 每个 Z 值仅对应一次发版，不可重复占用 | 已发 `1.0.7` 后不允许再出 `1.0.7` ✗ |
| **连续无空洞** | 不允许跳过某个 Z 值长期空置后再用 | 发到 `1.0.6` 后直接跳 `1.0.8`，`1.0.7` 永不出现 ✗ |

### 2.3 发版动作检查清单

每次发版前逐项核对：

- [ ] 新版本号 = 上一版本号，仅 Z + 1
- [ ] X、Y 与上一版本完全相同
- [ ] 无前导零、无字母/符号、段间仅用 `.`
- [ ] 该 Z 值历史上从未使用过
- [ ] 构建号（如 Android `versionCode`）已同步递增（通常为单调递增整数，与 Z 一一对应）

## 3. 适用场景

### 3.1 适用（推荐采用本规则）

- 产品**功能形态与架构长期稳定**，无重大版本跃迁诉求。
- 交付节奏以**持续小幅修订**为主：Bug 修复、文案/资源微调、小优化、合规更新。
- **本地应用 / 内部工具 / 长期维护型项目**，不需要用主/次版本对外传达"破坏性变更"或"重大新功能"。
- 团队希望版本号**简单、可预期、易追溯**，降低沟通与排错成本。

### 3.2 不适用（应改用语义化版本 SemVer 或其他策略）

- 需要对外用 **Major / Minor** 明确区分"不兼容变更 / 新功能 / 修复"的公开库或 SDK。
- 有市场化"大版本发布"动作（如 2.0 发布会），需版本号承载营销意义。
- 多团队/多模块对版本号有独立演进诉求的复杂系统。

> 若未来确需变更 X 或 Y，视为**规则升级事件**，须单独评审并书面记录，不属本规则日常发版范畴。

## 4. 演进示例（初始 → 连续发版）

### 4.1 正向连续演进表

初始版本 `1.0.0`，每次发版 Z + 1：

| 发版次序 | 版本号 | 相对上一版 | 典型发版内容 |
| --- | --- | --- | --- |
| 0（初始） | `1.0.0` | — | 项目首个正式版本 |
| 1 | `1.0.1` | +1 | 首版后首次修订 |
| 2 | `1.0.2` | +1 | Bug 修复 |
| 3 | `1.0.3` | +1 | 文案/资源微调 |
| 4 | `1.0.4` | +1 | 小优化 |
| 5 | `1.0.5` | +1 | 兼容性小修 |
| 6 | `1.0.6` | +1 | 性能微调 |
| 7 | `1.0.7` | +1 | 修复反馈问题 |
| 8 | `1.0.8` | +1 | 常规维护 |
| 9 | `1.0.9` | +1 | 末位进位前最后一版 |
| 10 | `1.0.10` | +1 | **跨 9→10 边界，仍仅 +1** |
| 11 | `1.0.11` | +1 | 继续单调递增 |
| … | `1.0.12` … | +1 | 持续修订，Z 无上限（≠归零） |

### 4.2 跨位边界说明

- 当 Z 从 `9` 到 `10` 时，**仅修订号 +1**，格式仍为 `1.0.10`，**不会出现 `1.1.0`**（那是变更了 Y，违反 §2.2）。
- Z 持续增长（10 → 11 → 12 … 直至上限），**绝不回绕为 0**。

### 4.3 反例对照（一律禁止）

| 起始 | 操作 | 结果 | 违规点 |
| --- | --- | --- | --- |
| `1.0.3` | 跳至 `1.0.5` | ✗ | 跳号（+2） |
| `1.0.4` | 回退 `1.0.3` | ✗ | 回退 |
| `1.0.5` | 改 `1.1.5` | ✗ | 改动前两段的冻结字段 |
| `1.0.5` | 写 `1.0.05` | ✗ | 前导零 |
| `1.0.7` | 已发后再发 `1.0.7` | ✗ | 编号重复占用 |
| `1.0.6` | 跳 `1.0.8`（7 空置） | ✗ | 制造编号空洞 |

## 5. 与构建号的映射（建议）

为兼顾"人类可读版本"与"系统唯一标识"，建议双轨并存：

| 字段 | 含义 | 本规则下的行为 |
| --- | --- | --- |
| 版本名 `versionName` | 对外展示，如 `1.0.12` | 严格遵循 §1–§2 的 X.Y.Z 与 +1 约束 |
| 构建号 `versionCode` | 系统内部整数，单调递增 | 每发一版 +1（如 100→101→102），可等于或大于 Z，但**必须唯一且递增** |

> 规则边界：`versionName` 受本规则强约束；`versionCode` 仅要求单调递增、不回退，二者不必数值相等，但应在发版记录中一一对应，便于回溯。

---

## 6. 一句话总纲

> **X.Y 立项即冻结，Z 每发版 +1，不跳号、不退号、不改前两段的格式与取值。**
