# 血糖随手记 · 技术方案设计

> 配套 PRD v0.2（Android 原生 App）。本文档为开发启动前的架构与实现方案，确认后据此落地。

---

## 1. 总体架构

采用 **MVVM + 单向数据流（UDF）**，分层清晰、逻辑可单测：

```
┌─────────────────────────────────────────────┐
│ UI 层 (Compose Screens + ViewModel)          │
│  收集 UiState (StateFlow) → 渲染             │
│  用户事件 → 派发 UiEvent → ViewModel 处理    │
└───────────────┬─────────────────────────────┘
                │ 调用
┌───────────────▼─────────────────────────────┐
│ 数据与逻辑层 (Repository + 纯逻辑)           │
│  RecordRepository / SettingsRepository        │
│  StatsUtils (纯函数) / Csv (纯函数)          │
└───────────────┬─────────────────────────────┘
                │ 读写
┌───────────────▼─────────────────────────────┐
│ 本地存储                                      │
│  Room (GlucoseRecord) + DataStore (Settings)  │
└─────────────────────────────────────────────┘
```

**关键点**：所有统计计算（StatsUtils）与 CSV 编解码（Csv）写成**不依赖 Android 框架的纯 Kotlin 函数**，可在 JVM 单元测试中直接验证（与微信小程序版 `utils/` 纯逻辑思路一致，逻辑可沿用）。

## 3. 数据层设计

### 3.1 Room Entity
```kotlin
@Entity(tableName = "records")
data class GlucoseRecord(
    @PrimaryKey val id: String,         // UUID
    val measureTime: Long,               // ms
    val value: Float,                    // mmol/L
    val period: String,                  // Period.key
    val note: String,
    val createdAt: Long                  // ms
)
```

### 3.2 DAO
```kotlin
@Dao
interface RecordDao {
    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun insert(r: GlucoseRecord)
    @Update suspend fun update(r: GlucoseRecord)
    @Delete  suspend fun delete(r: GlucoseRecord)
    @Query("SELECT * FROM records ORDER BY measureTime DESC")
    fun observeAll(): Flow<List<GlucoseRecord>>
    @Query("SELECT * FROM records WHERE measureTime BETWEEN :from AND :to ORDER BY measureTime ASC")
    fun observeBetween(from: Long, to: Long): Flow<List<GlucoseRecord>>
}
```

### 3.3 Settings（DataStore）
- `fastingMin` / `fastingMax` / `postprandialMax` 存为 Preferences 键（Float）。
- SettingsRepository 暴露 `Flow<Settings>`，写入即时生效、统计页实时响应。

### 3.4 Repository
- RecordRepository 封装 DAO，向 UI 暴露 `Flow<List<GlucoseRecord>>` 与增删改挂起函数。
- 应用级单例：在 `GlucoNoteApp` 中 `lazy` 构建 `AppDatabase`，Repository 经 ViewModel factory 注入。

## 5. 核心功能实现要点

### 5.1 记录录入
- 测量时间：先用 `DatePickerDialog` 选日期，再 `TimePickerDialog` 选时间，合并成 `measureTime`（毫秒），默认当前时刻；每次进入表单若未手动改过则刷新为当前时间。
- 快捷标签：`PeriodChips` 渲染 5 个快捷标签 chip（空腹 / 早餐后 / 午餐后 / 晚餐后 / 睡前），每个含**名称 + 一行说明**（PRD §3.1）；顺序固定，与首页快捷按钮完全一致。
- 数值：数字输入；保存前校验 `value`：空/≤0 提示；`<1.0 || >50.0` 弹 `AlertDialog` 二次确认。
- 编辑：点历史项回填表单；删除：二次确认后 `repository.delete`。

### 5.2 统计
- `StatsUtils.computeTrend(records, rangeType, filterPeriod?)` → `List<TrendPoint(ts, value, label, period)>`，`rangeType` ∈ {DAY, WEEK, MONTH, YEAR}，`filterPeriod` 为空代表全部标签；供图表描点与数值标签。
- `StatsUtils.computeRateByPeriod(records, settings)` → **按 5 个标签分别**返回 `{total, inRange}`（无论是否筛选，达标率始终按标签分组，便于横向对比）。
- `StatsUtils.computeRangeStats(records, from, to, filterPeriod?)` → `{avg, max, min, std, count}`，支持按标签筛选。
- `StatsUtils.computeBucketStats(records, granularity, filterPeriod?)` → `List<BucketStat(label, avg, max, min, rate, count)>`，`granularity` ∈ {DAY, MONTH, YEAR}；按自然日/月/年分桶聚合均值、极值与达标率，供「年月日区间分析」列表/柱状展示。
- **标签筛选**：StatsScreen 顶部提供「全部 / 空腹 / 早餐后 / 午餐后 / 晚餐后 / 睡前」分段切换，趋势图、区间分析与区间统计随筛选联动；达标率环形与进度条始终按 5 个标签分别展示。
- **年月日区间分析**：StatsScreen 提供「日 / 月 / 年」粒度切换，调用 `computeBucketStats` 渲染各时间桶的均值（柱状）与达标率（文字/进度），与标签筛选联动，便于对比「本月各天」「今年各月」走势。
- **趋势图（Canvas）**：x 轴时间、y 轴血糖；折线 + 数据点；**每个数据点上方绘制 `value` 文本标签**；目标区间用半透明阴影带叠加。
- **达标率（Canvas 环形）**：按整体或按标签绘制弧，中心显示百分比；下方各标签进度条。

### 5.3 导出 / 导入（SAF）
- 导出：`Intent.ACTION_CREATE_DOCUMENT`(type text/csv) 让用户选路径 → 写入 `Csv.toCsv(records)`（UTF-8 BOM）。
- 导入：`Intent.ACTION_OPEN_DOCUMENT` 选 CSV → `Csv.fromCsv(text)` 解析为 `List<GlucoseRecord>` → 批量 upsert 合并。
- `Csv` 纯逻辑层负责字段映射、逗号/换行转义、容错（缺列/脏行跳过并计数）。

## 6. 图表方案

- **零第三方依赖**：全部用 Compose `Canvas`（`DrawScope`）自绘。
- 折线图：手动坐标映射（min/max 留白）+ `Path` + `drawPoints` + `drawText`（数据点数值标签）+ 目标区间 `drawRect` 半透明。
- 环形图：`drawArc` 按占比分段，中心 `drawText` 百分比。
- 优点：体积小、可控、无许可证/兼容风险；符合「纯本地、轻量」定位。

---

## 7. 导航与依赖注入

- **导航**：Compose Navigation，路由常量 `home/records/stats/profile`，底部 `NavigationBar` 切换。
- **DI**：轻量化——`GlucoNoteApp` 持有 `RecordRepository` / `SettingsRepository` 单例；各 ViewModel 通过自定义 `ViewModelProvider.Factory` 获取 Repository。不引入 Hilt，降低构建复杂度（后续如需可平滑升级）。

## 9. 与 WindTone 的一致性与差异

- **一致**：同为 Kotlin + Jetpack Compose + Material3 + Room 技术栈，工程结构、MVVM、Flow 用法一致，可复用经验。
- **差异**：GlucoNote 为**全新独立工程**，不共享 WindTone 模块；定位「纯本地、无账号、轻量」，不引入 WindTone 的车载/悬浮窗等复杂能力。
- **构建环境**：需 Android SDK + Gradle；本机当前仅 JDK，工程在 Android Studio 中编译/运行（与 WindTone 工作流一致）。
