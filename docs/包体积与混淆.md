# 包体积与混淆（R8）

本文记录 GlucoNote 的 APK 体积构成、R8 配置，以及**不要碰的几处**。

---

## 1. 当前基线

| 项 | 值 |
|---|---|
| 版本 | v1.0.0（versionCode 1） |
| 产物 | `GlucoNote-v1.0.0.apk` |
| 体积 | **1.48 MB**（11 030 620 → 1 552 000 字节，−87%） |
| dex（未压缩） | 2.49 MB，1 个 |
| minify / shrinkResources | 均开启 |

> 参考：WindTone v1.3.0 universal 包 3.29 MB（含 Media3/ExoPlayer 等重依赖）。
> GlucoNote 依赖更少，落在 1.5 MB 量级是合理的。

## 2. 之前为什么会到 11 MB

两个原因叠加，各占一半：

### 2.1 `material-icons-extended`（主因）

```kotlin
// ❌ 曾经这么写
implementation("androidx.compose.material:material-icons-extended")
```

这个库包含约 **1500 个** Material 图标，每个都是独立的 `ImageVector` 对象，全部会编进 dex。
全项目实际只用了 5 个图标，其中 3 个（`Home` / `Person` / `Delete`）核心库就有，
只有 `BarChart` / `ListAlt` 属于 extended。

处理方式：

- 依赖换成 `material-icons-core`（约 40 个常用图标，由 material3 传递引入）；
- 缺的 `BarChart` 在 `ui/icons/AppIcons.kt` 用 `ImageVector.Builder` 自绘（约 30 行）；
- `ListAlt` 换成核心库的 `List`（视觉上同为列表，语义等价）。

> **以后缺图标怎么办**：先在 [Material Symbols](https://fonts.google.com/icons) 找到图标，
> 再判断是否在 core 集合里；不在就用 `ImageVector.Builder` 画，**不要**为了一个图标引进 extended。

### 2.2 `isMinifyEnabled = false`

release 完全没开 R8，未引用的 Compose 代码、反射元数据、注解全部留在包里。

现在：

```kotlin
release {
    isMinifyEnabled = true
    isShrinkResources = true
    proguardFiles(
        getDefaultProguardFile("proguard-android-optimize.txt"),
        "proguard-rules.pro"
    )
}
```

## 3. 混淆规则（`app/proguard-rules.pro`）

```
-keepattributes *Annotation*
-keep class com.gluconote.** { *; }
-dontwarn androidx.**
```

| 规则 | 为什么需要 |
|---|---|
| `-keep class com.gluconote.**` | Room 生成的 `*_Impl`、`Period` 枚举（`valueOf`）等按名访问，保守全留 |
| `-keepattributes *Annotation*` | Room / DataStore 依赖运行期注解信息 |
| `-dontwarn androidx.**` | Compose 内部有可选依赖的编译期引用，不 `dontwarn` 会让 R8 报缺类 |

> 应用自身代码量很小（keep 全留也只占几十 KB），真正的收益来自**库代码裁剪**，
> 所以这里选择保守规则：优先保证不因混淆出运行期问题。

### 3.1 开启 R8 后必须自查的三点

R8 出问题往往不在编译期，而在运行期。每次改动依赖后，按这三条过一遍：

1. **Room 是否还能建库**：`AppDatabase_Impl` / `RecordDao_Impl` 必须还能在 dex 里找到；
2. **枚举/反射路径**：新增枚举若通过 `valueOf` / `Class.forName` 使用，确认已被 keep；
3. **应用内更新**：`UpdateChecker` 解析 `latest.json` 用的是 `org.json`（平台类，不受混淆影响），
   但字段名是**约定字符串**，改动时必须同步 `gen-release-manifest.py`。

检查 dex 里类是否还在（不依赖 `strings` 命令，Windows 也能跑）：

```bash
python -c "
import zipfile
z = zipfile.ZipFile('app/build/outputs/apk/release/GlucoNote-v1.0.0.apk')
dex = b''.join(z.read(n) for n in z.namelist() if n.endswith('.dex'))
for c in ['AppDatabase_Impl','RecordDao_Impl','UpdateChecker','MainActivity']:
    print(c, dex.count(c.encode()))
"
```

## 4. 产物命名

Gradle 直接产出最终名字，不再依赖流水线临时改名：

```kotlin
// app/build.gradle.kts
androidComponents {
    onVariants { variant ->
        val suffix = if (variant.buildType == "release") "" else "-${variant.buildType}"
        variant.outputs.forEach { output ->
            (output as? com.android.build.api.variant.impl.VariantOutputImpl)
                ?.outputFileName?.set("GlucoNote-v$appVersionName$suffix.apk")
        }
    }
}
```

| 构建类型 | 产物名 |
|---|---|
| release | `GlucoNote-v1.0.0.apk` |
| debug | `GlucoNote-v1.0.0-debug.apk` |

> 之前是默认的 `app-release.apk`，分发时靠 CI 里 `mv` 改名 —— 名字里既没有应用名也没有版本号，
> 一旦改名逻辑失效就会发出无名包；且 CI 改名时漏了 `v` 前缀，与文档约定不一致。现已修正。

## 5. 还能再小吗（暂不做）

| 手段 | 预计收益 | 代价 |
|---|---|---|
| 按 ABI / 语言拆分 | 本应用无原生库，收益≈0 | — |
| 移除 `ui-tooling-preview` | 几 KB（仅编译期） | 无 |
| Compose 运行时换 `compose-runtime-tracing` 外的最小集 | 极小 | 维护成本高 |
| Baseline Profile 取代 `-dontwarn` 保守 keep | 体积不变，启动更快 | 需真机采样 |

当前 1.48 MB 已足够小（相对同类血糖记录应用普遍 10 MB+），暂不继续优化。
